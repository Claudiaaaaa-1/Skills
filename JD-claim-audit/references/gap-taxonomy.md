## 1. 断裂类型枚举

| `gap_type` | 判定条件 | 典型例子 |
| --- | --- | --- |
| `数值冲突` | 主张与强事实证据在同一对象上的数值不可同时成立 | 标题「100%真蚕丝」vs 属性「聚酯纤维 / 0%」 |
| `对象错位` | 证据指向的对象与主张对象不是同一个 | 检测报告针对 A 规格，主张写在 B 规格上 |
| `范围越界` | 证据只在特定规格、批次、地区、条件下成立，主张泛化到全体 | 某实验室恒温条件下的结果写成日常使用结论 |
| `时间或批次失效` | 证据已过期、被注销，或旧批次报告用于新配方 | 认证编号格式正确但已注销 |
| `资质缺失` | 功效、认证类主张没有对应资质证据 | 「防脱发」无功效资质 |
| `证据未核验` | 证据存在但只核验了格式，未核对权威库 | 检测报告编号格式正确，未查官方库 |
| `因果无据` | 功效结论没有充分依据支撑 | 由成分直接推出疗效 |
| `条件泛化` | 特定条件下的结果被写成普遍结论 | 「销量最强」缺限定范围与佐证 |
| `图文不一致` | 图片展示与文本属性冲突（v2 能力，v1 只登记不判定） | 主图 1 级能效 vs 属性 3 级能效 |
| `无断裂` | 主张与证据对齐，或主张本身为纯表达 | 「柔软得像云朵」 |

抽象维度（主张对象、时间、范围、条件、数值、因果、资质、感受性）用于**拆解**一条主张，上表用于**判定**一个断裂。两者不是同一层：维度是观察角度，类型是结论标签。把 8 个拆解维度和 8 个权衡维度（吞吐、精度、解释、口径、风险、申诉等）混为一谈是常见的口径事故。

## 2. 类型到状态的映射

| 断裂类型 | 状态 | 理由 |
| --- | --- | --- |
| `数值冲突`、`对象错位` | `BLOCK` | 已有强事实直接否定主张，补证无法改变结论 |
| `资质缺失`、`条件泛化`、`因果无据` | `REQUEST_EVIDENCE` | 商家补交资质或限定条件后可复核，先让信息变完整 |
| `证据未核验`、`时间或批次失效`、`图文不一致`、`范围越界` | `HUMAN_REVIEW` | 需要外部核验或跨模态判断，模型没有能力独立定论 |
| `无断裂` | `PASS` | 对齐成立，或纯表达无需证据 |

严重度顺序：`BLOCK` > `HUMAN_REVIEW` > `REQUEST_EVIDENCE` > `PASS`。

**规则优先的正确含义**：词库、正则、白名单只负责召回和打标，不直接出终判。唯一例外是黄赌毒一类绝对违规硬红线，允许短路为 `BLOCK`。若让词库先出终判，「100%真蚕丝」这类合法材质陈述会在语义纠偏之前就被拦下。

证据缺失一律标 `UNKNOWN` 并进入 `REQUEST_EVIDENCE` 或 `HUMAN_REVIEW`，不得用常识补全后给 `PASS`。

## 3. 审核决策维度

课堂口径为「6 个维度」，实际列举为 7 项，此处按 7 项保留并向业务确认：

1. 绝对化 / 唯一性用语
2. 功效宣称
3. 资质
4. 产地
5. 材质成分
6. 价格优惠
7. 感受性营销

维度的作用是保证主张抽取不遗漏类型，不是逐项打分。同一句话在不同类目下的合法性可能完全不同，见第 5 节。

## 4. 证据可信度三级

| 级别 | 来源 | 处理方式 |
| --- | --- | --- |
| `强事实` | 结构化属性、可对接官方库的检测报告编号、认证编码、官网直连信息 | 可直接参与数值与对象比对 |
| `需交叉验证` | 商家自填参数、上传的资质图片 | 存在 PS 与伪造风险，需第二来源或人审 |
| `纯表达` | 标题、主图营销话术、修饰词 | 先解析成可验证主张，否则不作为证据 |

把三级压平成「有证据 / 没证据」，会丢掉最重要的信息：证据本身可不可信。

## 5. 类目差异与语境例外

审核不能脱离类目、位置和事实条件独立判断。

| 表达 | 食品 | 化妆品 | 床品 / 饰品 | 团体 / 记录类 |
| --- | --- | --- | --- | --- |
| 「100%天然」 | 需证明无添加，且不得暗示功效 | 需符合标签管理规定 | 需材质成分支撑 | — |
| 「最强」 | 绝对化用语，通常违规 | 通常违规 | 通常违规 | 有吉尼斯纪录等佐证时可用 |
| 「医生推荐」 | 非医疗产品不得涉医 | 需真实授权与资质 | 非医疗产品不得涉医 | — |
| 「100%真蚕丝」 | — | — | 材质比例陈述，**不是**绝对化用语 | — |

因此「感受性营销一律判假阳性」并不成立。「王者级触感」是否违规依赖类目与语境，与绝对违规 / 通常违规 / 有条件可用三分法必须一起用。

## 6. 失效案例库

旧链路（关键词过滤 + OCR + 词库命中 → 人工复核）的两类失效，是设计本 skill 的依据。

**假阴性 / 漏放**

| 案例 | 为什么旧链路漏掉 |
| --- | --- |
| 8000mAh 写成 2 万 | 不含高危词，词库无从命中 |
| 标题「天然蚕丝」vs 属性「聚酯纤维」 | 不含极限词，且没有跨字段比对 |
| 主图 1 级能效 vs 属性 3 级 | OCR 只识别文字，不理解图与文的关系 |
| 认证编号格式正确但已注销 | 只校验格式不查库，查库有单次成本 |

**假阳性 / 误伤**

| 案例 | 为什么旧链路误拦 |
| --- | --- |
| 「柔软得像云朵」「王者级触感」 | 把表达强度等同于事实陈述，修辞被直接判欺诈 |
| 「100%真蚕丝」 | 词库不区分语境，材质比例被当成绝对化用语 |
| 多 SKU 共用详情图 | 未保留规格映射，某一 SKU 缺报告导致全部拦截 |

两类失效同源于一处：判断停留在「词」，没有建立「主张 ↔ 证据」的关系。加长词库只会同时加剧两端的问题。

## 7. 已知盲区

以下必须写进 `boundary`，不得由模型猜测后省略：

- 未核验检测报告在官方库中的真伪；「编号格式正确但已注销」仍可能漏放。
- 未覆盖主图与 SKU 的图文关系，`图文不一致` 在 v1 只登记、不判定。
- 未核验实物；真正的货不对板需要售后、差评、投诉、抽检、职业打假工单回流做真值。
- 「补充证据」之后的复审、次数上限、超时、防刷、幂等重跑属上游链路职责。
- 规则知识库的版本管理与回归机制不在本 skill 内。

盲区不是待修的 bug，而是当前信息条件下无法诚实跨越的边界。让它出现在输出里，比让模型编一个结论更安全。
